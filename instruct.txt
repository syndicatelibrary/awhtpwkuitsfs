Create a complete, single-file HTML tool (no frameworks, only HTML, CSS, and vanilla JavaScript) that functions as a GitHub public repository file browser.

The tool should behave like a lightweight CDN-style file index viewer.

========================
CORE FEATURES
========================

1. USER INPUT
- Input field to enter a GitHub username
- "Load" button to fetch data

2. REPOSITORY LIST
- Fetch and display all public repositories using:
  https://api.github.com/users/{username}/repos
- Show repo names in a clean list/grid
- Include basic info: name, description (if available)
- Clicking a repo loads its file structure

3. FILE / FOLDER BROWSER
- Use:
  https://api.github.com/repos/{owner}/{repo}/contents/{path}
- Display files and folders separately:
  - Folders first
  - Files below
- Clicking a folder navigates into it
- Maintain current path state

4. BREADCRUMB NAVIGATION
- Show current path like:
  repo / folder / subfolder
- Each segment clickable to go back

5. FILE TYPE HANDLING
- Highlight file types with icons or labels:
  - audio (.mp3, .wav, .flac)
  - images
  - text/code
- No downloading or opening files, only listing names

6. SEARCH / FILTER
- Live search bar to filter visible files/folders by name

7. SORTING
- Toggle sorting:
  - A → Z
  - Z → A
  - folders first always

========================
ADVANCED FEATURES
========================

8. RECURSIVE FILE SCAN MODE (IMPORTANT)
- Add a toggle: "Scan Entire Repo"
- Use Git Trees API:
  https://api.github.com/repos/{owner}/{repo}/git/trees/{branch}?recursive=1
- Extract and display ALL file paths
- Filter to show only specific types (especially audio files)
- Warn user if repo is large

9. AUDIO LIBRARY MODE
- Toggle: "Audio Only"
- Filters for:
  .mp3, .wav, .flac, .ogg, .m4a
- Display clean list of filenames (no folders needed in this mode)

10. CACHING SYSTEM
- Cache API responses in memory (JS object)
- Avoid duplicate API calls when navigating back

11. LOADING + ERROR STATES
- Show loading spinner/text
- Handle:
  - invalid username
  - rate limit errors
  - empty repos

12. RATE LIMIT AWARENESS
- Display a small warning:
  "GitHub API allows ~60 requests/hour without authentication"
- Minimize unnecessary API calls

========================
UI / DESIGN
========================

- Clean, minimal dark theme
- Responsive layout
- Scrollable panels:
  - left = repos
  - right = files
- Sticky header for search + path
- Smooth hover effects

========================
TECHNICAL CONSTRAINTS
========================

- MUST be a single HTML file
- No external libraries or frameworks
- Use only fetch API
- No backend
- No authentication required
- Must work when opened locally in browser

========================
CODE QUALITY
========================

- Well-structured, readable code
- Separate logic into functions:
  - fetchRepos()
  - fetchContents()
  - fetchTree()
  - renderRepos()
  - renderFiles()
- Use comments to explain key parts

========================
GOAL
========================

The final result should feel like a professional GitHub file explorer / CDN index tool, especially useful for browsing and remembering filenames (like audio libraries).

Return ONLY the full HTML file.
